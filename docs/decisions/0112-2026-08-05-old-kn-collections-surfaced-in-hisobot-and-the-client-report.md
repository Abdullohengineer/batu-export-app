## 2026-08-05 — Old-KN collections surfaced in Hisobot and the client report

**Context.** `old_kn_collections` recorded the draw and `old_kn_pools`' derived balance dropped correctly, but there was no report row — a client collecting old Konditirskiy was invisible in Hisobot and the client report. Explicitly deferred at Stage 2 (see "Opening stock Stage 2: collect old-washed, old-KN, old-raw"). Confirmed still open before writing anything: `report_rows`' live definition only unioned three kinds (`report_kirim_rows`/`report_chiqim_rows`/`report_raw_dispatch_rows`) — no old-KN kind existed. `supabase/migrations/0063_report_old_kn_rows.sql`.

**The `chiqim_raw` precedent applied cleanly, with one deliberate deviation.** New `report_old_kn_rows` mirrors `report_raw_dispatch_rows`' exact 27-column shape — nulls where a concept doesn't apply (no serial, no barcode2, no calibre, no box mass; `old_kn_collections` has none of these). `owner_id`/`type_id` are sourced from `old_kn_pools` (the material's true owner), not `chiqim_requests` — there is no `kirim_orders`-equivalent table to source them the way raw dispatch does via the serial's own order. In practice these should always agree (a client can only collect against their own pool), but the pool is the authoritative source, matching the *spirit* of the precedent (read the material's real owner) rather than its literal join path.

**The direction-filter bug fixed preemptively, not rediscovered.** `report_filtered_rows`'s structural early-return gained `or (p_direction = 'chiqim' and r.kind = 'chiqim_old_kn')` in the same migration that added the kind — this is the exact bug raw dispatch shipped with (`20260731124242_raw_dispatch_direction_filter_fix.sql`): filtering Hisobot to CHIQIM specifically made every raw row vanish because the early-return had no arm for the new kind. The detail-filter gating arm (calibre/barcode2/wash_cycle/lab_verdict) mirrors `chiqim_raw`'s shape exactly.

**`oldKn` is its own top-level `get_client_report` section, not nested inside `raw`.** Old-KN is a distinct product, not raw material — two new CTEs (`old_kn_events`, `old_kn_collected_total`), one new JSON key (`collectedKg` + a flat `collections` list, period-scoped, no opening/closing balance — `old_kn_pools` tracks that separately and is out of scope here). Deliberately **not** touched: `reconciliation` — old-KN pools are a separate balance system from the raw three-bucket reconciliation, and `balancesKg` must stay unaffected. Everything else in the 500-line function is byte-identical to the pre-migration version.

**Origin rule applied — dispatch/departure side, correctly unfiltered by construction, not by an added filter.** `report_old_kn_rows` never references `kirim_orders.origin` at all; there is no `kirim_orders` row involved in a pool collection. Per CLAUDE.md's origin-filtering rule and the precedent this session already established ("departure/dispatch side stays unfiltered everywhere" — old-washed/old-raw dispatch needed zero reporting-view changes for the identical reason), a collection counts as real outbound regardless of whether the source was opening stock.

**`report_totals`**: `chiqim_old_kn` added to `total_kg_out`'s `kind in (...)` list. `total_kg_tara_out` untouched — old-KN carries no box mass (`box_mass_kg` is `null` on these rows), already correctly excluded.

**Frontend**, mirroring the raw-dispatch precedent file-for-file: `reportQuery.ts` (new `OldKnReportRow`, `weightKg` named to match the existing kinds so the shared `row.kind === 'kirim' ? row.effectiveQtyKg : row.weightKg` ternary needed no changes), `ReportTableRow.tsx`/`ReportRowCard.tsx` (new branches alongside the existing `chiqim_raw` ones), new `OldKnRowDetail.tsx` (mirrors `RawDispatchRowDetail.tsx` minus box mass/passport link — no serial to open a passport for), `reportExport.ts` (new branch, blank serial column — honestly, since there is none).
