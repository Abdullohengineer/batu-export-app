## 2026-07-30 — Serial passport: nakladnoy + headline/table restructure

**Context:** The passport (§3.2.5) was missing the KIRIM nakladnoy document, and every section rendered as run-on text paragraphs with large inline photos instead of a scannable structure.

**Part 1 determination, checked before writing anything.** `KirimForm.tsx`'s "Hujjat rasmi · ixtiyoriy — Mijoz nakladnoyasini biriktirish" field has captured the nakladnoy since the KIRIM form was built (`kirim_orders.doc_photo`, `kirim-photos` bucket). Checked Ombor's own `IntakeAcceptForm.tsx` too, per the task's explicit instruction to check both capture points — no document field there, only `pile_photo` (a photo of the physical raw pile, already shown, a different thing). Read `get_serial_passport` directly: its `order` object never selected `doc_photo` at all. **Determination: captured but hidden, not case 2** — no KIRIM-form change needed, confirmed rather than assumed. Fixed with one additive key in the RPC.

**One-section proposal before building everywhere, per the task's own gate.** Built Buyurtma (including the new nakladnoy row) and Darvoza first, verified live end to end — thumbnail loads the real signed photo, click opens a full-resolution lightbox stacked above the passport (z-60 vs the passport's own z-50), Escape closes the lightbox first and the passport on a second press, missing photos produce no row at all. Presented this as the proposed pattern before touching the remaining four sections; **user confirmed apply-to-the-rest as-is.**

**Design decisions, applied once, consistently:**
- **Table shape:** `label | value` rows (`FieldTable`), matching this codebase's own `th`/`td`-table convention (Hisobot, Ombor qoldig'i) rather than inventing a new one. A field/photo that doesn't apply yet is an omitted row, not an empty one — same "missing shows nothing" rule the photos already followed, now extended to every field.
- **Thumbnails:** `GatePhoto.tsx` gained a `thumbnail` + `onOpen` mode — 56×56px, no internal caption (the table row's own label already carries that context, so the old thumbnail's what/who/when caption stack would have been redundant), clicking calls `onOpen(url, label)` instead of the previous `target="_blank"`. Additive and backward-compatible (`onOpen` optional) — confirmed via grep that the passport was the only consumer of `thumbnail={true}` anywhere in the codebase, so nothing else could regress.
- **Lightbox:** new, lives at the outer `SerialPassportModal` level (not inside `PassportBody`'s own scroll container, so it isn't clipped), `z-[60]` stacked above the passport's `z-50`. Backdrop/× both `stopPropagation` before closing, so a lightbox click never also closes the passport underneath it (they're siblings inside the same click-to-close outer div). Escape handling centralized in one listener at the outer level — closes the lightbox first if one is open, the passport otherwise — rather than a second competing listener inside the lightbox itself.
- **Already-tabular content left alone:** the per-pallet breakdown tables (Moyka cycle, Jo'natishlar) and the current-position table were already proper multi-column tables, not run-on text — out of this task's own restructure scope, untouched.
- **The aggregate "Rasmlar" gallery removed, not kept alongside the new inline thumbnails.** It used to show every photo a second time at the bottom; once each section carries its own photos inline, keeping it would mean every photo renders twice. One photo previously shown *only* in that gallery — the CHIQIM lab sample photo (`cycle.lab.samplePhoto`) — was never in the inline Moyka block before this task; folded into the new Moyka lab table so removing the gallery doesn't lose it. `cycle.lab.note` was deliberately **not** added as a new row — it was never shown anywhere before (not even in the old gallery, which is photos-only), and adding previously-unshown text is outside this task's scope (photos + table restructuring only).
