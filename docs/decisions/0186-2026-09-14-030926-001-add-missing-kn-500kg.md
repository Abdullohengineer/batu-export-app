was entered against this serial, matching the existing KN-5/02-3/04-3 rows from that day).

attributing it to one would be false audit data — same reasoning as decision 0161).

**First attempt reopened the wash cycle (`closed_at = null`), following the older 0161
precedent — reverted before this was considered done.** 0182 (2026-09-12, later than 0161)
established the cycle doesn't need reopening at all: `finished_pallets` has no FK/trigger
dependency on `wash_cycles.closed_at`, and `computeLossDisplay`/every SQL consumer
(`yield_rows`, `kirim_line_state`, `get_serial_passport`, Hisobot) recomputes `sent - received`
live off `finished_pallets` at query time — nothing about the loss figure is cached or frozen

realized "Yo'qotish", and has real side effects the task didn't ask for: it drops the serial out
of `yield_rows` (`closed_at is not null` gate) and puts it back in Ombor's receive picker as
still-open. Restored `closed_at` to its original timestamp; the insert alone is sufficient.
