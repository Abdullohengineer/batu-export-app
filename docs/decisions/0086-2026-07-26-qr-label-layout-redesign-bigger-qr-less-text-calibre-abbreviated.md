## 2026-07-26 — QR label layout redesign: bigger QR, less text, calibre abbreviated

**Before, confirmed from source (both `drawAndCommit` in P1PrinterPlugin.java and `renderLabel` in barcodeLabel.ts, shared by Barcode #1 and #2):** QR was 10mm, top-left at (3, 1.5) on the native 40×30mm label — left a 27×10mm dead zone to its right, unused. Below it, 5 stacked lines: full barcode value, parent serial, `type · calibre` (full word, e.g. "Konditirskiy"), weight, company. For Barcode #1, the barcode and serial lines printed the *exact same value* twice (`toPrintOptions` in Barcode1Display.tsx sends `barcode: data.serial, serial: data.serial` — a pre-existing duplicate, not something this pass introduced). No configured QR quiet-zone margin (API default 0); relied entirely on a thin 0.5mm gap to the text below. Web's QR was already centered (unlike native's left-aligned original) at the same 10mm, text centered and auto-shrinking/ellipsizing below it.

**Also found and fixed in passing: a stale comment in barcodeLabel.ts, unrelated to this task but in the exact code being touched.** Lines 27-33 claimed the canvas was 800×480 from a "round(50 × 7.992)" calculation — but `LABEL_MM.w` is 40, not 50, and `NATIVE_W = Math.round(LABEL_MM.w * DOTS_PER_MM)` actually computes 320, not 400 (confirmed by executing the exact expression live: `DOTS_PER_MM=7.992…, NATIVE_W=320, CANVAS_W=640`). The prose was stale from before that constant changed; it never affected behavior since `QR_SIZE_PX=160` (old) was already set correctly against the real 16px/mm ratio, not the wrong comment's implied 20px/mm. Corrected the comment to 320×240/640×480 while already editing this exact block for the QR resize.

**Calibre abbreviation mapping confirmed against the live `calibres` table, not guessed.** `code` is `'01'`–`'08'` / `'KN'`, `label` is `"Kalibr N"` / `"Konditirskiy"` — neither is directly `"K4"`, and only `label` reaches the label composers (`Barcode2LabelData.calibre`/`calibreLabel` param), so `abbreviateCalibre` derives it from the label text: `"Konditirskiy"` → `"KN"`, `/^Kalibr (\d+)$/` → `"K" + digits`, anything else passes through unchanged. Deliberately a pattern match, not a 9-entry lookup table — calibres are Sozlamalar-managed (admin-editable, see `CalibresSection.tsx`/`useCalibres.ts`), so a hardcoded table would silently stop abbreviating any calibre added after Kalibr 8; the regex handles future ones automatically, and the fallback means an unrecognized label never crashes or blanks. Two independent copies exist (TypeScript in barcodeLabel.ts, Java in P1PrinterPlugin.java) — same reason `stripBarcode2Prefix` already has two: native and web can't share code, and both comments cross-reference the other to flag if one drifts.

**Two content questions were real judgment calls, not implementation details — asked before coding rather than guessed:** (1) whether to drop "type" (Tur) from Barcode #2's printed line now that calibre is abbreviated and merged with weight — user chose to **keep it, prefixed** (`typeName · abbrevCalibre · weight kg`), not drop it, so the new merged line carries the same information as before, just abbreviated + consolidated, never less. (2) `Barcode2Display.tsx` has a *third* rendering path beyond the two the task named (native print, `barcodeLabel.ts` preview) — a separate on-screen HTML summary row next to the on-screen QR canvas (line 140, `{serial} · {type} · {calibre} · {weight} kg · {owner}`) — user chose to **update it too**, so all three surfaces agree rather than leaving this one showing stale full-detail content after the sticker itself no longer does.

**New layout: QR 16mm (up from 10mm — +60% linear, +156% area), centered horizontally, dominant.** Native: 3 left-aligned lines below it (was 5) — full barcode value (fallback if scanning fails, font size kept at the original 2.2mm since native `drawText` has no auto-shrink and this line's worst-case length didn't change) · `typeName · abbrevCalibre · weight kg` (font kept at the original typeLine's 2.5mm — abbreviating calibre saves roughly what adding the weight suffix costs, so the safe-length calculus this size was originally tuned against didn't actually change) · company (unchanged). Web mirrors the same 3-line content but keeps its own pre-existing, more robust sizing mechanism (auto-shrink for the barcode line, ellipsize for the small fields) rather than adopting native's fixed-size approach — text switched from centered to left-aligned to match native, per the task's explicit ask that both surfaces read the same way. Serial dropped entirely from printed text on both — it still lives inside the encoded QR value for lookups, completely unchanged (verified: `stripBarcode2Prefix`/`barcodeEncoded` construction untouched in this pass).

**Barcode #1 gets a small, necessary side-effect, not a redesign.** `drawAndCommit` and `renderLabel` are shared between both barcode kinds — giving the QR more room meant Barcode #1's original 5 lines (2 of them the exact-duplicate noted above) no longer fit comfortably. Merged its `type` and `weight` onto one line (`typeName · weight kg`), mirroring the exact same consolidation Barcode #2's redesign already required, and dropped the duplicate serial line — the same fix, applied for free. Web's Barcode #1 additionally keeps its pre-existing `date` field (never printed natively — a web-preview-only field per Barcode1Display.tsx's own comment), now 3 fields instead of 4. Nothing about Barcode #1's actual *content* was asked for or added beyond what sharing the layout code with Barcode #2 required.
