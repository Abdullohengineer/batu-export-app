## 2026-07-25 — Ombor printing gaps: pre-Tugallash reprint, true W2 ordering

**Context:** three named gaps in Ombor's finished-goods printing flow, following on from the P1 printer integration.

**Inspected and reported before coding, per the task's gate — two of three turned out already solved or needing no new data, one turned out to need a small schema addition:**

**Requirement 3 (print button on KIRIM W2) — already done.** The earlier P1 printer task already added `Barcode1Display` per-row in `OmborIntakeTab.tsx`'s "2 · Qabul qilingan" list, unconditionally (not gated by the `defaultOpen` auto-print flag) — it already works for older accepted lines exactly as asked. Confirmed live, nothing to build.

**Requirement 1 (reprint before Tugallash) — confirmed existing data, no query change.** `useMoykaOutput`'s `OutputSerial.pallets` already carries every already-received pallet for an in-progress serial, and `OmborTayyorTab.tsx` already had a `palletList()` helper rendering exactly this with a `Barcode2Display` per pallet — just only reachable from inside the Tugallash-confirm view. Fix is pure presentation: a new `expandedPallets` toggle (mirrors Window 2's own existing `expandedCompleted` pattern) surfaces the same helper independent of that flow.

**Requirement 2 (W2 newest-first) — the real surprise, flagged rather than silently patched.** `completed` was already sorted, but by `lastReceivedDate` (last pallet's receipt date) — a proxy, because `wash_cycles` had no column recording the actual Tugallash moment (confirmed live: `id, serial, cycle_no, status, final_loss_pct, voided_at`, nothing else). That's the real bug: a serial finished today whose last pallet was physically received days earlier sorts by that older date, not today. Applied, flagged rather than silently skipped or silently applied without mention (task's own "Flag if a query change is needed"):
```sql
alter table wash_cycles add column finalized_at timestamptz;
```
Set once, in `handleTugallash`'s existing upsert, at the real finalization moment. Left null for all 20 existing `final` rows (no historical record exists to backfill honestly) — `useMoykaOutput.ts`'s sort key is `finalizedAt ?? lastReceivedDate`, so already-sorted older rows don't regress and every new Tugallash from here on gets the precise signal. No RLS change, fully additive, zero rows affected beyond the new nullable column.
